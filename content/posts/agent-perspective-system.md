# 会提问还不够：人与 Agent 协作真正缺的是视角系统

## 前言

AI 时代最流行的建议，是让人学会更好地提问。这个建议没有错，甚至是大多数人用好 AI 的第一道门槛。不会提问的人，会把模糊需求直接扔给模型，然后得到一份看似完整、但没有办法验收的结果。

但对已经会主动提问的人来说，真正的瓶颈会很快往后移动。问题不再是「我有没有问」，而是「我知不知道自己缺了哪种视角」。一个人可以很会追问目标、边界、约束和交付格式，但仍然可能看不见自己的判断盲区。他可能会问很多问题，却都在同一个认知框架里打转。

主动提问解决的是表达和澄清问题；更高一层的能力，是系统性地识别自己的视野局限，并让 Agent 在合适时刻补进你原本不自然调用的专家视角。

人与 Agent 协作真正需要的，不只是一个更会回答的 AI，也不只是一个更会追问的 AI，而是一个能帮助人持续校准判断、形成验收标准、发现自身盲区的视角系统。

---

## 一、主动提问是入口，但它只能暴露你已经隐约意识到的缺口

主动提问的价值很明确。用户说要做一个产品方案，AI 不应该立刻写方案，而应该追问目标用户、使用场景、成功标准、约束条件和交付格式。用户说要写一篇文章，AI 也不应该立刻铺陈论点，而应该先问读者是谁、文章要改变读者什么判断、哪些例子可以支撑核心观点。

这类提问能把模糊任务拉清楚，也能减少大量无效执行。但它主要处理的是用户已经隐约知道、只是没有表达出来的东西。更难的部分是：很多关键判断，用户脑子里本来就没有。

一个没有工程经验的人，不会因为 AI 多问几句就自然知道什么叫可回滚、可测试、可观测。一个没有产品经验的人，不会因为 AI 追问用户画像就自动拥有对真实场景的敏感度。一个没有设计训练的人，也不会因为 AI 问他喜欢什么风格，就能判断信息层级、视觉密度和交互节奏。很多时候，用户不是没表达清楚，而是缺少那个领域的视角。

「提问技巧」这个说法容易把问题讲窄。它把人机协作描述成表达层问题，好像只要人更会问，AI 就能更好地帮他。但真实瓶颈往往在判断层：用户不知道什么值得问，不知道答案好不好，不知道哪里应该怀疑，不知道哪些结果不能交付。

更高一层的 Agent，不只是帮你追问需求，而是在你已经能主动提问之后，继续帮你识别：你现在的问题，是缺信息、缺表达，还是缺一个完全不同的判断视角。

---

## 二、更隐蔽的危险：在 AI 的帮助下更确信了一个窄视角

主动提问还有一个隐藏风险：它可能让人感觉自己已经想得很充分。你和 AI 来回追问了很多轮，问题被拆开了，结构被搭起来了，结论变得更顺了，于是你更容易相信自己已经覆盖了关键变量。

但「更顺」不等于「更可靠」。研究者把这种现象称为认知漂移¹——人和 AI 反复交互后，主观信心可能持续上升，但认知可靠性未必同步提升。AI 可能让你更有把握，却没有让你更接近真实。

这件事有一个刺眼的推论：会提问的人比不会提问的人更难察觉这件事。不会提问的人得到低质量答案，失望来得早；会提问的人则可能得到高质量包装后的窄视角——结构完整、语言流畅、推理链看起来也像那么回事。而这种完整感本身，会加深错误的确信。

AI 是放大器，不是均衡器。²过去软件的输出相对稳定，Word、PPT、Excel 不会因为用法差一点就产生数量级差异；但 AI 时代，提示词、流程、选择和判断都会被放大。它不会自动把所有人拉到同一水平，反而会把视角差异、判断力差异、taste 差异拉得更大。

有意思的是，这个方向也有它的反面。一项针对宝洁公司的现场研究发现³，商业背景和技术背景的人单独工作时往往产出"偏科"方案，各自偏向自己的强项；但当引入 AI 协作后，两类人的方案质量趋于均衡——AI 补足了单一视角的缺口。这说明 AI 确实有补位能力，但前提是人知道自己在哪里偏了。不自知的放大，和自知后的补位，是两件截然不同的事。

比如一个擅长框架搭建的人，和 Agent 协作时往往推进很快。他能迅速定义概念、拆出层级、画出路径，然后让 Agent 一路执行。但这种能力的阴影面是，他可能过早命名，过早收敛，过早把一个「看起来结构完整」的东西当成「值得做」的东西。此时最有价值的 Agent，不是继续帮他补章节、扩论据、做配图，而是切换视角问他：这个框架的前提是什么？什么情况下它会失败？如果只能砍掉一半内容，哪一半其实并不重要？

用 MBTI 只是一个方便的隐喻：ENTJ 式的人擅长结构和推进，就需要 INTP 式的逻辑拆解，ISFJ 式的具体用户感受，ISTP 式的实证拆机，ENFP 式的可能性发散。重点不是人格标签，而是承认每个人都有稳定的认知形状。一个 Agent 如果只顺着你的形状走，它会越来越像你的高级执行器；一个好的 Agent 应该在关键时刻补上你不自然调用的视角。

主动提问是第一层元认知能力，视角系统是第二层。前者让人把问题说清楚，后者让人意识到自己为什么只能这样问。

---

## 三、真正有价值的 Skill，是专家验收标准的封装，而不是工具说明

这也解释了为什么 skills 会变得重要——而且是以一种比通常理解更根本的方式。

很多人把 skill 理解成「让 Agent 学会一个工具」，比如会用某个 API、会生成某类文档、会操作某个软件。这个理解太窄了。真正有价值的 skill，承载的是专家在某个工作领域经过大量验收后沉淀下来的判断力——它知道什么叫做对，不只是知道怎么操作。

一个 Product Verification skill 的价值，不在于它会不会打开自动化测试工具，而在于它知道什么样的产品变更必须验证，哪些路径必须覆盖，哪些「测试通过」仍然不代表体验合格。一个强制追问前提的 skill，也不是单纯多问几十个问题，而是在强制引入一种职业纪律：开工之前必须把前提、边界、风险和验收标准问清楚。

有一个细节很能说明问题：判断力不是声明出来的，是在大量验收中校准出来的。⁴让工程师对 50 个 AI 生成的 PR 逐一做 code review 并校准评分，这个过程本身就是品味训练——不是告诉 AI「你要有品味」，而是通过反复判断来内化什么叫做「更好」。

单个 skill 解决的是一个点的问题，多个 skill 编排起来，才能解决线和网的问题。⁵视角系统不是一个单点 prompt，而是一组可被调度、可被串联、能共同形成验收闭环的判断模块。

Prompt 模板优化的是表达，skill 注入的是判断力。前者让你更会说，后者让 Agent 临时借给你一种职业训练后的注意力分配方式。

未来找 skill，不应该被理解成「找一个工具」，而应该被理解成「找一种我当前缺失的专家视角」。写代码缺的是测试视角，做产品缺的是用户旅程视角，写文章缺的是反方视角，做研究缺的是实证视角，做设计缺的是审美和信息层级视角。Agent 的能力不只是调用工具，而是判断此刻应该请哪一种视角进场。

---

## 四、视角系统不应该只会质疑用户，还要帮用户表达和验收

如果只把这个系统写成「AI 来质疑你」，就遗漏了人机协作更完整的面貌。很多时候，用户真正需要的是表达、翻译、校准和验收，而不是被挑战。

有一类产品正是在帮非专业背景的人表达模糊意图——不是替用户变成设计师，而是把用户低分辨率的意图翻译成更可讨论、更可修改、更可验收的中间物。这个方向揭示了协作的另一面：好的 Agent 不是永远站在反方，而是在不同阶段切换角色。

Notion Custom Agents 的开发历程很能说明这个问题。⁶它从 2022 年开始反复重做四五次才成型。早期团队把 Notion 自己的 block 数据结构映射成 XML 暴露给模型，后来发现这其实是在迁就自己的系统，而不是迁就模型的认知方式。真正的转折，是把数据表达改成模型熟悉的 Markdown，把复杂 JSON 查询改成模型熟悉的 SQL。教训很直接：别把系统里不必要的复杂度暴露给模型，要尽可能给它它真正能理解和操作的东西。

好的 Agent 产品不是在用户和模型之间多加一层花哨界面，而是不断重写表达面、工具面、权限面和 eval 面，让人的意图、系统的能力、模型的理解方式对齐起来。Notion 甚至把 eval 分成回归测试、产品发布质量、frontier/headroom 三层，并专门设计只能通过 30% 的内部压力测试，目的不是证明模型没变差，而是理解模型下一步往哪里走。

一开始帮你表达模糊意图，中间帮你补齐缺失视角，执行时帮你维持验收标准，结束后帮你沉淀新的判断。这比「AI 应该主动提问」更完整，也比「AI 应该质疑你」更准确。

## 五、好的 Agent 不是更主动，而是知道什么时候应该介入

如果把视角系统产品化，它不会只是一个更聪明的聊天框。它至少需要四层结构：认知画像、workflow 画像、skill / 视角库，以及介入时机判断。

认知画像记录用户稳定的优势和盲区，不是为了贴标签，而是让 Agent 知道什么时候应该顺着用户推进，什么时候应该轻轻打断。workflow 画像记录用户最近反复在做什么，哪些步骤经常手动补，哪里经常返工，哪些任务长期没有验收标准。skill / 视角库提供专家判断模块，让系统知道当前该引入工程、产品、设计、研究、反方还是用户视角。介入时机判断则决定它什么时候说话，什么时候闭嘴。

最后这一层最难。主动介入必须嵌入用户已有工作场景，挑战强度和时机要可控。⁷一个总是质疑你的 Agent 会让人烦；一个从不质疑你的 Agent 只是高级自动补全。真正的产品难点不是让 AI 变得更主动，而是让它知道哪些时刻值得打断。

值得打断的时刻有一个共同特征：**高确信，但低验证**。用户高确信但没有证据时，用户刚刚给一个新概念命名时，用户要进入长执行链路但验收标准为空时，用户把自己的体验当成用户体验时，用户反复手动修同一种问题时——这几个时刻都是确信度超过了证据的时刻。

在这些时刻，Agent 不需要长篇说教，只需要提出一个高质量问题。比如：「我用实证视角打断一下，这个判断有没有一个最小可跑的验证样本？」或者：「我用用户视角补一刀，真实用户第一次打开时最可能卡在哪里？」又或者：「如果这个框架是错的，最先坍塌的是哪一个前提？」

这种提问的目的不是否定用户，而是把他原本不擅长调用的思考方式临时接进来。

好的 Agent 不是把所有视角、所有 skill 一次性砸给用户，而是判断此刻哪个视角最该出现。确定性高的任务用代码完成，不需要每次都绕语言模型一圈；工具选项过多时做渐进式过滤，而不是一次性展开——这个原则同样适用于视角调度。

## 六、未来的强协作者，不是最会问 AI 的人，而是最会让 AI 参与判断系统的人

人与 Agent 的关系不应该停留在「人提问，AI 回答」，也不应该只升级成「人下命令，AI 执行」。更有价值的形态，是一个持续校准系统：人提供目标、动机和最终责任，Agent 提供执行力、记忆、外部视角和反复校验，skill 提供被封装的专家经验，认知画像提醒人的稳定盲区，验收标准把所有视角落到结果上。

AI 时代真正稀缺的，不是会写复杂 prompt 的人，而是能借助 Agent 快速补齐视角、建立标准、发现自己盲区的人。未来的强协作者，不一定是最会问 AI 的人，而是最会让 AI 参与自己判断系统的人。

提问技巧解决的是我怎么把问题问出来；视角系统解决的是我怎么知道自己少看了什么。前者提升表达质量，后者提升判断质量。

我们缺的不是一个更会回答的 AI，也不只是一个更会追问的 AI。我们缺的是一个能帮助我们看见自己看不见之处，并把这些盲区转化成验收标准、skill 和长期记忆的协作系统。

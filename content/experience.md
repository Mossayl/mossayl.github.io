## 腾讯混元 — Auto-Eval 策略研究
**2026.02 – 2026.06 ｜ 模型评测 / 数据合成**

混元模型团队前沿 Eval 研究，主导 tool-use（agent）与 multi-turn 两个方向，从问题定义、环境构造、数据合成到评分链路的端到端落地，目标是补齐腾讯原生场景下的 agent 评测能力。

**Tool-use（Agent）评测 — 0→1 建立原生场景的 agent 评测能力**
业界 tool-use 评测大多基于通用或公开 API，无法回答"agent 在真实业务里到底能不能用"这一更关键的问题，于是从零搭建原生场景的评测体系。真正的难点在于真实业务既没有可供评测的可控环境、复杂多步任务也难以保证 ground-truth 与难度——为此拟合真实业务的数据表结构，重建多表数据库与 MCP tool server，把业务场景还原成可控、可复现的工具环境；又针对写入类任务设计快照差分验证，让"做对没有"可被确定性判定，并按多跳推理、集合运算、跨实体联动、时序依赖、多步写入等能力维度分层校准难度。最终落地数百个 agent 任务，支撑单题数十次 tool call、多处数据变更的复杂多步评测。

**Multi-turn 评测（Hy-MultiTurn）— 填补长程多轮的 benchmark 空白**
多轮交互在 Codex / Cursor 等 agent 与 chatbot 场景中都极普遍，但现有评测难以衡量——公开多轮数据集轮次过短、且严重缺乏中文场景，而各公司 in-house 测评集多由线上回流改写、轮次同样偏短，靠 bad case 造数据的方式也难以真正衡量模型在真实场景下的能力。核心难题因此落在如何造出真实、长程且可判定的中文多轮数据：从线上回流的真实对话反向拆解影响多轮交互的根因，抽象为约束遵循、长上下文状态更新、固定历史检索绑定、gate 决策、隐藏越权抑制等若干类 failure-mechanism 模式，据此拟合生成长达数十轮的中文长对话评测集；并搭配 deterministic checker 与 item-level LLM judge 双评分、把 rubric 拆到 item 级以规避黑盒整体打分。最终完成主流模型全覆盖，产出可定位约束级失败的 leaderboard。

## Moonshot 月之暗面 — Kimi 模型能力产品化
**2024.01 – 2025.03 ｜ 产品经理**

在算力与成本受限条件下，0→1 主导拍照解题、语音通话、搜索等高复杂度功能链路，覆盖需求挖掘、交互设计、模型工程到数据策略闭环。

- **拍照解题**：完整功能定义上线，达到日均数十万使用人数的规模。把图像噪声前置到产品与工程侧解决，构建多分类 Routing 将 query 分发至 Math / Code / 通用模型，定义 K12 图像数据与视觉噪声标准指导 SFT 优化。
- **语音通话**：功能定义上线并达到日均十万级使用。定位 LLM 回答质量瓶颈为 ASR 错误并设计 benchmark 推动准确率显著提升；落地语音字幕、音色克隆、微信分享等核心 Feature。
- **搜索策略**：作为搜索 SFT 数据 Owner，设计触发搜索链路，抽象多类用户感知强的 Badcase（时效冲突、信息源冲突、概念混淆），定义数据与标注标准。
- **微信文档上传**：参考打印机文档应用设计 App→小程序→App 的文件传输链路，打通微信生态文档上传。

**2025.07 – 2026.02**

- **超播治理**：上线门禁 + 押金双策略，从前置校验与根源预锁两端治理超投消耗，显著降低大盘超播率。

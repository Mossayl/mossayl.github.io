## 笔记 1

封面字：

大厂做不好 Agent
不是因为没人懂模型

封面图：

`/Users/wangye/workspace/blog/static/images/posts/ai-agent-war-big-tech-trap/xhs-note-01-cover.png`

正文：

先说一个常见的误解：大厂做不好 AI Agent，是因为没有懂模型的人。

这个判断太浅了。

字节的朱文佳、阿里的周靖人、百度整个管理层都有很深的模型背景。真正的问题不是没人懂，而是——组织架构让懂的人也做不出正确决策。

豆包、元宝、通义千问，背后的组织都是产品线、数据线、模型线分得干干净净。在短视频、电商、广告时代，这套分工很合理。

但 Agent 产品需要的不是三条线各做一段再拼起来。它需要一个极小的团队，同时看到三层，做出一体化判断：

模型层：知道什么数据能让模型在特定场景下表现更好
数据层：知道怎么从业务场景里提炼高质量训练信号
产品层：知道用户的工作流长什么样，harness 该怎么设计

以 Claude Code 为例，Agent 的进化是一个紧密的飞轮：

观察用户工作流 → 设计 harness 抽象 → 收集执行数据 → 模型针对性优化 → 回到产品层验证

三个齿轮必须同步转。大厂的组织设计，恰恰把三个齿轮放在了三个部门里。

问题还有另一层。

大厂中高层的认知框架，很多还停留在旧逻辑：

旧逻辑：掌握分发渠道 → 喂内容 → 留用户 → 卖广告
新逻辑：构建 solid harness → 适配模型能力 → 留住工作流 → 从生产力提升中收费

这两套逻辑不是优化关系，是完全不同的世界。

少数有视野的年轻人要花大量精力向上说服，而不是向下执行。一个错误决策消耗半年，外面的模型公司已经迭代了三轮。

这就是为什么我越来越相信：

Agent 时代最危险的不是没技术，而是还在用上一个时代的组织方式，做下一个时代的产品。

未来 1 年，赢家大概率不是「模型最好的」，而是「工作流锁定最深的」。

而工作流锁定，恰恰不是一个大组织靠分工就能自然做出来的东西。

能做出来的，一定是一个小团队，三种能力叠在同一批人身上，在真实工作流里跑出来的。

## 笔记 2

标题候选：
- 纯应用层 AI 创业，有一笔账你必须先算清楚
- Cursor 和 Perplexity 的路，不是所有 AI 创业公司都能走
- Agent 创业最难的不是做产品，是 token 成本结构

封面字：

AI 应用创业
先算清 token 账本

封面图：

`/Users/wangye/workspace/blog/static/images/posts/ai-agent-war-big-tech-trap/xhs-note-02-cover.png`

正文：

如果一个 AI 应用公司没有自己的模型，它到底靠什么长期赚钱？

这是我最近反复想的一个问题。

短期当然可以靠产品体验赢。Cursor、Perplexity 都证明过：在模型之上做足够厚的产品层，确实能创造很大价值。

但这里有一个结构性问题，值得认真算一算。

模型公司卖 API 服务，只需要承担推理成本。

独立应用公司卖产品，除了推理成本，还要额外支付模型 API 费用。

这中间多出来的一层，在普通聊天产品里还没那么尖锐。但 Agent 不一样——

Agent 完成一个任务，可能要调用模型 10-20 次。token 消耗是简单问答的几十倍。如果 token 成本下降放缓，或者高质量模型阶段性涨价，应用层公司的试错空间会被迅速压缩。

这还没算完。

当模型公司开始做自己的原生应用层，它们同时占据两个优势：

成本优势：不需要向自己收 API 费用，边际成本更低
能力优势：最新的模型能力，往往在自家产品里先用，再开放给第三方

所以纯应用层创业不是不能做，而是必须满足几个条件：

1. 场景足够垂直，模型公司短期不愿亲自下场
2. 工作流足够深，用户迁移成本高到不合理
3. 有自己的数据飞轮，真实业务数据让 Agent 越用越好
4. 不只是包一层聊天框，有真正的产品壁垒

缺任何一个，模型公司一旦补上原生应用层，两边的优势会同时压下来。

这也是为什么我觉得 Agent 创业的窗口不会太长。

你竞争的对手，不是另一个 App。

是同时拥有模型、算力、数据、分发、品牌的公司。

能活下来的应用层公司，一定不是「AI 版某某工具」。

而是把某个高价值工作流吃得足够深——深到模型公司不值得为你这一块亲自重做。

这个「足够深」的标准，会比大多数创业者预期的要高很多。
